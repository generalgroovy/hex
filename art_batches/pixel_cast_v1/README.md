# Full-cast pixel source and assembly

October 2 extension of the three-character pilot to every current playable
identity. Original source sheets are generated individually with the built-in
image tool and remain immutable. Roster identities come from the live catalog,
not old labels in the style image. Prompt sets and per-character receipts record
references, observed directions and unresolved motion details.

The three workers own Small, Middle and Large source folders. Only the lead
assembles runtime banks, changes shared code or runs engines. Existing pilot
sources and working packages remain preserved.

`python -B art_batches/pixel_cast_v1/build.py --available` assembles available
sources and a review board but does not publish an incomplete runtime manifest.
Without that option, every live identity is required. Four physical rows store
idle, two contact poses and empty-hand casting; neutral passing beats are reused
by index. That saves one-third of decoded atlas pixels versus six duplicated
rows, without hiding the unfinished passing/sidestep artwork.

Assembly uses authorized alpha cleanup, component isolation, uniform source-
sheet scale and registration only. It never invents limbs, deforms bodies or
bakes the old weighted mesh. A per-character `assembly.json` may record observed
row mappings or a reviewed seam correction; source sheets stay untouched.

Native inspection of facings, contacts, cast seams, portraits and fallback
transitions is required before the full bank is offered as a playable checkpoint.
Structural tests and different image hashes do not prove realistic gait. Low/air
actions still use the existing renderer; this is not all-action completion.
