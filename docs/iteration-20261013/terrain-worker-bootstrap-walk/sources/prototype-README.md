# Ignored worker validation experiment — unqualified

This prototype extends the exact preserved original stream at `../T8-before/wellspring_terrain_stream.gd`, SHA-256 `83c1ee7a896ca60a92f2b691c9c7cfd54faff32fffdc33d84181e38ccdcdf0ca`. It does not extend the withdrawn sliced implementation and is not referenced by the game. No engine has parsed or executed this checkpoint yet.

The original public `configure`, request/prefetch, readiness, pump and shutdown interfaces remain. The inherited residency, texture submission and synchronous tooling path remain unchanged. A normal pump retrieves ready loader tokens on the main thread, verifies exact dimensions/format/mipmaps/manifest metadata, and takes a detached pixel snapshot. Only a task-local `HashingContext` processes those immutable bytes off-thread. Its mutex publishes a small scalar result after hashing; it never protects the expensive hash itself. Image reconstruction and texture creation remain on the main thread, using only the joined and digest-verified bytes.

`pending` owns at most two items across decoding, collected images, hashing and verified uploads. `tasks_started` and `tasks_joined` witness task lifetime. Ordinary pumps poll completion before joining; final shutdown may wait. Obsolete running tasks remain owned until joined, including a quick return to the same ID. Their cancellation is sticky and prevents publication; any renewed demand receives a fresh owner afterward. Reconfiguration refuses any owned work. Normal suspension never blocks for a task. The worker never sees a scene, image, texture, loader, stream or authority reference.

New status fields include `active_hash_tasks`, `decode_pending`, `validation_pending`, `obsolete_owned`, `worker_wait_pumps`, `obsolete_worker_wait_pumps`, and conservative logical payload peaks. These are fixed aggregate values, not per-frame histories. Main-thread profile stages include detached-byte preparation, task dispatch/collection and reconstruction. Worker elapsed time is separately reported; it can include descheduling and must not be added to a frame interval or subtracted as an assumed gain. Logical payload counts exclude physical allocator/COW, pool, hash-context and driver memory.

The time target remains a target. Image access, reconstruction, texture submission and a completed-task join are indivisible primitives; an individual primitive may overrun. The first snapshot/submission may require a later pump before completion, and an obsolete task can temporarily delay renewed demand. Neither lower latency nor faster throughput is established.

Before any retention decision, require independently reviewed source, checked parsing, actual worker ownership/error/cancellation tests, full and cropped exact pixel validation, mutable-original snapshot isolation, wrong-digest rejection, no readiness before validation, shared two-owner limits, zero remaining tasks after ordinary final teardown, and repeated native old/new readiness/CPU/walking comparisons. Keep all warmups, invocation order, maximums and failures. Main-thread improvement alone cannot offset worse actual arrival or walking behavior without an explicit design decision.

Primary API support is narrow: [WorkerThreadPool](https://docs.godotengine.org/en/4.6/classes/class_workerthreadpool.html) requires eventual collection of every submitted task and warns that small tasks may become slower; [thread-safe API guidance](https://docs.godotengine.org/en/4.6/tutorials/performance/thread_safe_apis.html) excludes active scene-tree and GPU/image manipulation from this design; [Mutex](https://docs.godotengine.org/en/4.6/classes/class_mutex.html) documents synchronized access and destruction requirements. These sources do not prove this prototype correct or faster on the installed Godot 4.7.1 engine.
