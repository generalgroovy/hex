## Working rules

- Quality means understandable choices, responsive execution, truthful feedback,
  recoverable mistakes and useful combinations. A feature count or green suite
  cannot establish charm, fun or a finished high-end game. Prioritize the weakest
  visible player experience over adding another subsystem.
- Root owns integration, registries, wire/build identity, shared docs and every
  Godot import/test/capture/profile/export. At most three workers with exact,
  non-overlapping write paths; shared code gets one writer and independent review.
- Start from a concrete defect or falsifiable improvement; preserve positive
  controls, real paid routes and the last runnable state. Freeze for verification.
- Prefer catalog-derived facts and links over duplicate rules/counts. Keep
  [the balance contract](../docs/HEX-BALANCE-CONTRACT.md) and roster current.
- Never weaken validation, hide threat geometry, discard paid events, change
  cadence/caps, or add stale mutable caches to obtain a performance number.
- Preserve dirty work, originals, useful failed receipts and protected builds.
  Archive concise evidence before any explicitly scoped old-build cleanup.
- No commit/push, publication, deployment, account changes, spending or historical
  pointer promotion without the user's corresponding authority.
- Finish a coherent checkpoint and report remaining gates; do not start an
  indefinite goal or consume the remaining quota merely to continue.
