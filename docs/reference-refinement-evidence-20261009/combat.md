## Concrete audit findings

1. The apparent moving-field/equal-strength-only text in `ChemistryGuideModel` is a retained legacy reader. The current `PlayerCompendium.configure` replaces the primer and `detail_paragraphs` routes reaction details to current `hex_pair_lines`. Rewriting this unused copy would not establish an actual player benefit.
2. Current shared documents still call Charge a fast Bolt, although the inherited launch candidate makes all eight Bolts 360 px/s. Root owns correction of these shared contracts.
3. Heavy secondary range used the physical impact point, but secondary cover tests used the projectile center. With a 30 px Heavy collider these could disagree by 30 px, allowing a visible impact to damage around a corner that blocks the actual blast origin, or denying an exposed target. The implemented correction in `src/sim/hex/hex_projectile_combat.gd` anchors the cover ray to the same impact point, offset by at most one fixed coordinate unit per axis toward the free projectile center to avoid an inclusive wall-face self-hit. Range, damage, ownership, height, protection, strength and finite material remain unchanged.
4. Incoming-damage perks changed Health while existing hit events still reported the pre-modifier amount. All eleven `PlayerResourcesSystem.damage` callsites now report captured Health before minus Health after. This includes projectile, splash, Spray, beam, optical beam, product, Conflagration, pressure and legacy chemistry routes. Recording the actual delta also handles overkill and a hit that crosses its own perk threshold; recomputing the multiplier afterwards would be incorrect.

## Character identity adaptation

The user requested a distinct perk for every character and race while retaining the current controls. `src/content/character_perk_catalog.gd` contains all thirty existing characters in production wire order. Race definitions and simulation policy are owned by the other agents. The H.E.X. design inference is to reward an identifiable current posture or resource window and attach an immediate competing cost, keeping both visible in Gallery and Compendium.

Every character has a different condition-plus-effect-key signature; changing a percentage cannot satisfy uniqueness. This is mechanical uniqueness, not evidence that every pairing is equally enjoyable or competitively balanced. All conditions read existing authoritative state. There is no new hidden history, cooldown, action button, damage bonus, material multiplier or airborne allowance. Individual factors are bounded to 0.85–1.20, with damage resistance no stronger than 0.90; the runtime combines race and character within its documented limits and preserves positive costs and damage.

These are original adaptations of the cited principles, not claims that an established game uses these exact perk pairs. Startup checks the posture and resources before Flux payment; that spell's cooldown checks the state when startup releases. A character can therefore earn the startup part and miss the cooldown part, or vice versa. The cooldown belongs to the spell across slots and does not impose a global cast or movement lock. The production Details explains this and the normal resource waits.

`tests/support/character_perk_audit.gd` verifies roster/wire coverage, thirty distinct signatures ignoring numerical factors, compact names and summaries, valid condition/effect vocabulary, bounded benefit and drawback, primary-reference fields and deep-copy isolation. The integrated identity suite supplied by the movement agent adds true/false windows and actual simulation routes. Compact summaries derive their percentages from the same catalog used by runtime, and distinguish cast startup and spell cooldown from Health/Flux/Stamina recovery.

## Cross-review and remaining qualification

- The movement correction was independently reviewed against `.godot/reference-refinement-baseline/movement/`: after paid air-dodge commitment, steering stores the minimum of its previous speed budget and the current unslowed air vector. This prevents braking from restoring earlier speed next tick while preserving neutral flight, protection, payment and commitment. Root owns execution of its tests.
- World/menu review covered the modal stick latch and physical-key fallback, current-input practice guidance, authoritative perk projection, actual-font line budgets, and the native capture's unchanged-world/equipped-state checks. No blocker was found in those code paths by static inspection. Review did find stale source playstyles denying unique passives, and escalated them for root's authoritative content correction instead of hiding them with UI string replacement.
- Movement-agent cross-review caught an ineffective proposed timing modifier: cast recovery is presentation/attunement state, not the gate for casting again. The integrated design therefore adjusts the actual spell-owned cooldown at release. No global cast lock was added. Acceptance must exercise same-spell retry refusal/admission, not merely inspect a timer.
- Geometry and resource accounting can be proven by these deterministic scenarios. A claim that all game aspects are now optimal, that thirty identities are equally strong, or that precedent proves improved player enjoyment would exceed the evidence. Human movement/combat trials, match telemetry and the existing wider roadmap remain necessary.
