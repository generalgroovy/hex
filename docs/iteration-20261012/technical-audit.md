## T2 optional viewport attribution

The tooling implementation adds `-ViewportRenderTiming` to the [native profile wrapper](../../scripts/profile-gameplay.ps1) and `--profile-viewport-render-timing` to its [Godot collector](../../scripts/profile-gameplay.gd). It is off by default and incompatible with `LightObserver`. It enables timing only on the existing root window and at most two existing POV viewports. A fixed three-row group shares each admitted `render_setup` observation; the existing 12,000 groups per case and 120,000 groups per run remain the bounds. No Bootstrap, player VSync, frame cap, simulation frequency or viewport update policy is changed.

Pre-draw observations use the effective RenderingServer update policy and record the requested node policy separately. Investigation found that the scene node retains a requested `UPDATE_ONCE` after the server consumes it; treating that cached request as current eligibility would query stale readings. The optional collector now reads the server policy, with potential render-thread synchronization counted as observer cost. An absent or inactive viewport has null CPU/GPU readings and is not queried. First eligible readings, replacements and resumes after inactivity carry a warmup/stale-risk label. Numeric zero stays numeric; it is not evidence that a GPU timer is supported or that work took zero time. Callback frame IDs identify observation time only. Godot exposes the last stored CPU/GPU timing without a public source-frame ID, so even continuous samples cannot be added into a matched current-frame total. Summaries keep warmup and continuous readings separate and record callback bookkeeping totals, which exclude the uncalibrated engine timestamp overhead. These restrictions follow the [RenderingServer timing API](https://docs.godotengine.org/en/4.6/classes/class_renderingserver.html#class-renderingserver-method-viewport-get-measured-render-time-cpu) and its [stored timestamp implementation](https://github.com/godotengine/godot/blob/4.6/servers/rendering/renderer_viewport.cpp); the project's 4.7.1 engine still needs its own native check.

Owned instrumentation is disabled on normal completion, explicit failure, report-I/O failure and finalization. The pure receipt validator checks mode, fixed role order, raw/budget alignment, update policy, null versus numeric readings, warmup/resume/replacement labels, finite values and cleanup accounting. After the effective-policy repair, root passed 182 pure assertions: measurement 35, arming 54, portable 8 and gameplay-profile 85. The native lifecycle receipt `.godot/iteration-20261012/viewport-native-lifecycle-b.json`, SHA `6dcca8a03f75aebcb8d9eca9745f806102239d6fc26e67d4f5cf6ca8591440a0`, passed 17 actual pre/post groups across eight stages: absent, active, disabled, ONCE, consumed ONCE, resumed, replacement and freed.
