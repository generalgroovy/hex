# H.E.X. engineering execution prompt

Improve the next ten minutes of H.E.X. play with a bounded, verified change.
Creative freedom serves readable decisions, responsive movement, useful elemental
counterplay and charming original pixel art. More systems, agents, files or
assertions are not themselves progress.

## Start from current authority

Read [HEX-RESUME](HEX-RESUME.md), the active row of the
[single implementation queue](OVERHAUL-IMPLEMENTATION.md), then only relevant
[SPECIFICATION](../SPECIFICATION.md) sections and source. The resume owns build
IDs, launch commands and acceptance state; do not copy them into this prompt.
Older evidence qualifies its exact source/package only.

Confirm the actual checkout, dirty boundaries and protected runnable build.
The current contract is Windows, six elements, four spell families, twelve
positions, thirty identities, 63 bounded whole-hex reactions and an eight-player
cap. Keep exact scope checks passing. Broader capacity and proposed content are
gated future work, not implied by existing data or reference images.

## Choose and delegate one coherent improvement

Identify a concrete defect or falsifiable player benefit before implementation.
Use the [aspect manifest](ASPECT-DELEGATION.md) and existing role cards; at most
three workers plus root, exact disjoint write paths, explicit contract, regression
matrix and stopping condition. Shared subsystems get one writer and independent
review. A clean audit is preferable to an invented fix.

Root owns integration, registries, wire/build identity, shared docs and every
Godot import/test/capture/profile/export. Agents report exact changed files,
checks actually run and NOT_RUN gates. Do not launch engines against changing code.
Reuse registered tests and assets; do not spawn one permanent agent per data row.

## Implementation and optimization rules

- Preserve paid resource/matter accounting, input ownership, deterministic contact
  order, exact whole-hex membership, height/protection, timings and same-build
  networking. Refusal must not spend or silently activate a different option.
- Optimize measured repeated work using conservative math, immutable sharing and
  bounded correctly invalidated caches. Preserve strict validation, extension
  fallback and complete state/events/bytes; no stale mutable trust or cadence cuts.
- Measure actual paid empty/distributed/dense/cover workloads, full-path cost,
  setup, memory and p95/p99/cold tails. A fast kernel is not a faster whole game.
- Keep authored pixels registered and fixed-scale, travel independent of aim,
  volume-first body sizes, same wall clearance and truthful threat cues.
  Held keys are not full animation cycles. No mesh morphing, projectile tails,
  material trails or idle orbits; short bounded character wakes are presentation only.
- Research uncertain mechanisms using primary sources when useful. Do not claim
  private implementations of inspiration games or copy their assets.

## Verification and handoff

Start with a reproducible control; add adversarial and positive regression cases.
For documentation edits, run `scripts/check-current-scope.ps1` and
`scripts/current-build-summary.ps1 -CheckPath README.md` before expensive gates;
each top-level `docs/*.md` needs an explicit `Status:` within its first ten lines.
Do not weaken these guards to accommodate a rewrite.
After the smallest fix, inspect the diff and run focused checks. At a frozen
integrated boundary run Full/import/identity/boot and applicable actual-input,
native, network or package gates. Repeat only when changed source or an unresolved
risk requires it. Keep failed receipts; never reclassify them as passing.

Distinguish code correctness, rendering, animation feel, listening, competitive
balance, package/install, localhost and physical Internet. Dense sustained 120 Hz
requires measured acceptance. Do not claim universal quality from assertion totals.

Maintain one contract, one queue and one short resume, with evidence links.
Archive superseded narrative before replacing it; preserve originals, dirty work,
useful failed evidence and working builds. Clean only owned disposable artifacts.
Do not edit personal memory without an explicit request.

Honor the latest user cutoff, checking actual usage at meaningful boundaries;
reserve enough room to repair, verify and hand off before the floor. Do not
continue just to consume quota or create an indefinite goal. A requested reset
must use an available authorized mechanism, never a fabricated action or purchase.

Local implementation and relevant local validation are in scope. No commit/push,
publication, deployment, account/spending/router changes or historical checkpoint
promotion without corresponding user authority. Return a runnable checkpoint,
the exact way to test it, meaningful changes and remaining acceptance gates.
