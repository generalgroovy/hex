2. Inventory complexity by player learning cost, source duplication, hot-path
   work and migration risk. Prefer subtracting redundancy over adding a layer.
3. State the behavior that cannot change before each edit. Preserve save/wire
   compatibility, admission/payment, timing, phase/owner coverage and UI actions.
4. Implement the smallest useful change. Do not remove compatibility code merely

5. Test equivalence, mutation boundaries, denial cases and native presentation.
   Measure targeted work reduction; do not equate CPU microbenchmarks with FPS.
6. Critique the result: did complexity move elsewhere, did a new cache become a

7. Freeze production source; run Full/native/Windows packaging, then update
