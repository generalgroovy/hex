# H.E.X. simplification guidance

Status: supporting method, updated October 11, 2026; historical run details are archived, not queued work.

Reduce duplicated facts, repeated calculation, ambiguous labels and maintenance
paths without removing useful movement execution, aim/travel independence,
resource trade-offs or elemental choices. The
[current specification](../SPECIFICATION.md) owns the six ingredients,
63 compositions, eight deliveries, 504 spell definitions, twelve positions and
30 playable identities. Current work and qualification are in the
[implementation record](OVERHAUL-IMPLEMENTATION.md) and [resume](HEX-RESUME.md).

1. Establish the concrete problem and the behavior that must remain invariant.
   Inspect actual dependencies and ownership before deciding that a file is unused.
2. Make one bounded change. Preserve save/wire compatibility, paid admission,
   deterministic order, visibility and truthful warning geometry.
3. Compare against preserved behavior, including mutation, refusal and overflow.
   A cache must have exact invalidation, a bound and a safe fallback.
4. Measure the affected complete workload when performance is the goal.
   Microbenchmarks, native callbacks, engine FPS and physical presentation are
   different observations.
5. Freeze and qualify the changed scope. Keep useful failures and working builds;
   do not remove a migration, independent oracle or original asset because its
   name contains an old version.
6. Consolidate explanations into their authoritative documents. Preserve a needed
   historical body exactly before replacing it; retain backlinks where useful.

See the [execution guide](OVERHAUL-PROMPT.md) for delegation and engine ownership.
Latest explicit user authorization governs actions: the October 11 source
cleanup/commit/push request supersedes earlier batch restrictions on those
actions. Installer, account, system-setting and unrelated publication work are
not implied.

The [exact September brief](archive/source-publication-20261011/SIMPLIFY-WITHOUT-LOSS.md)
records the earlier four-delivery/eight-element run, its tempo changes and
deferred ideas. It is evidence of that work, not a current tuning instruction
or a requirement to keep exactly two local builds.
