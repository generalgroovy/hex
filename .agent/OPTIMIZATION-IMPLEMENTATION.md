# H.E.X. implementation efficiency

Status: supporting guidance, updated October 11, 2026; not an implementation queue.

The [execution guide](OVERHAUL-PROMPT.md) owns the working method,
[specification](../SPECIFICATION.md) owns rules, and
[resume](HEX-RESUME.md) owns exact source/package identity and qualification.
Use the [implementation record](OVERHAUL-IMPLEMENTATION.md) for the current
authorized task; a completed record does not automatically start another batch.

| Principle | Application |
|---|---|
| One authority | Validated runtime/catalogs; do not maintain competing numeric tables |
| Bounded work | Concrete defect or player benefit, exact ownership, regression and stopping condition |
| Reuse | Existing assets, movement, importer and authority before another framework |
| Optimization | Measure representative work; bound caches and retain exact fallback/invalidation |
| Evidence | Separate source correctness, rendered pixels, timing, exported bytes and human acceptance |
| Recovery | Preserve dirty work, original assets, profiles, useful failures and working fallback |
| Cleanup | Verify dependencies and archival needs before removing retired writers or duplicate outputs |

Current scope is Windows, 120 Hz, an eight-player cap, six ingredients,
63 compositions across eight deliveries, 504 runtime spells, twelve positions,
21 ancestries and 30 playable identities. Derive detailed counts and timing from
current source rather than copying historical tables.

Use the PowerShell 7 [development entry points](../docs/DEVELOPMENT.md).
The October 11 user request authorizes relevant cleanup, documentation and source
commit/push; it does not itself publish a binary release or certify new gameplay.
The [exact earlier guide](archive/source-publication-20261011/OPTIMIZATION-IMPLEMENTATION.md)
retains its old eight-element/57-spell scope as history.
