# H.E.X. focused aspect delegation

Status: current reusable dispatch guidance, updated October 11, 2026; historical assignments are archived.

This document defines ownership and review, not a second task queue. Follow the
latest user request, [specification](../SPECIFICATION.md),
[implementation record](OVERHAUL-IMPLEMENTATION.md) and [resume](HEX-RESUME.md).
Historical role cards and batch names cannot override current scope or schedule
work on their own.

## Shared dispatch contract

1. Each assignment names a concrete problem or falsifiable benefit, unchanged
   invariants, exact writable paths, expected checks and stopping condition.
   Start read-only when the issue is uncertain.
2. Use at most three specialists plus root. One writer owns each shared subsystem;
   others review it without concurrent edits. A specialist owns a concern, not
   unconditional access to every related file.
3. Root integrates shared Bootstrap/registries/wire identity and serializes every
   Godot import, test, capture, profile and export. Do not qualify moving source.
   Report checks actually executed and distinguish prepared or NOT_RUN work.
4. Preserve dirty user work, original art, personal saves, independent reference
   fixtures, useful passing/failing evidence and protected runnable builds.
   Cleanup requires an inspected dependency/retention boundary, not a date filter.
5. Follow explicit current user authorization. On October 11 the user authorized
   relevant cleanup, updated documentation and source commit/push. Earlier
   no-commit/no-push batch clauses do not veto that request. Binary releases,
   installers, deployment, account/spending or system changes are separate.
6. Reuse established tools/assets and existing tests. Repair demonstrated defects
   before arbitrary tuning; use primary reference evidence without claiming
   private implementations or copying other games' assets.
7. Preserve deterministic state, independent travel/aim, 120 Hz stepping, paid
   resources, contact order, protection meanings and visibility unless the
   authorized change explicitly revises that contract. Rendering may simplify
   work but must not change collision or conceal real danger.
8. Current content is six ingredients, 63 compositions, eight deliveries,
   504 spells, twelve positions, 21 ancestries and 30 playable profiles.
   Ice/Charge are derived effects. Coverage must include relevant old and new
   cases without mistaking registry completeness for balance.
9. Specialists review another owner's invariants and tests. Native appearance,
   physical input, listening, network behavior and sustained performance have
   different evidence requirements; a static review does not qualify them.
10. Return changed paths, before-copy/archive location, observed checks, concrete
    limitations and the next required integration action. Stop when the bounded
    assignment is complete; do not invent an endless follow-up queue.

## Ownership patterns

| Concern | Typical writer | Independent review |
|---|---|---|
| Movement/input/resources | One movement owner | Replay, payment, transition and protection boundaries |
| Spells/chemistry/statuses | One combat owner | Finite budgets, contact order, cover, snapshot and refusal controls |
| Map/presentation/UI | Explicit disjoint file owners | Actual paths, input focus, truthful cues, native readability and bounded work |
| Shared integration/publication | Root | Specialist verification of source identity, evidence and dependency closure |

Use content matrices for relevant directions, sizes, families, ingredient sets
and boundary values. Do not create one permanent agent per data row or duplicate
registries across workers. [Development](../docs/DEVELOPMENT.md) describes the
current PowerShell 7 source/test/build entry points.
