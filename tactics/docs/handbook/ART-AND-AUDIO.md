# Art, animation, effects, and audio

This handbook describes the web tactics game at release 45, inspected on 2026-10-20 at source commit `947019572508ad0e20bb1dbbfe19c0ebeeee7148`. Paths are relative to the web application root; in the combined H.E.X. repository that root is `tactics/`. The Godot game's art and runtime remain a separate application.

The current presentation is pixel fantasy: dark warm outlines, restrained material palettes, brass costume accents, ivory panels, evergreen framing, and grounded character silhouettes. Motion should explain a physical action or a changing elemental material. Trees, walls, idle creatures, and whole character cutouts should not sway merely to make the screen busy.

## Character performance and alignment

The animation row contract is zero-based:

| Row | Performance |
|---:|---|
| 0–2 | Six-frame walk: front three-quarter, right profile, rear three-quarter |
| 3–5 | Six-frame cast in those same three views |
| 6 | Six-frame hit reaction, front three-quarter |
| 7 | Six-frame defeat, finishing in a persistent fallen pose |

`animationView` maps eight gameplay facings onto the three painted views, mirroring left-facing play. Hit and defeat currently use one authored view. Idle uses the first cel; there is no separate six-frame idle row. Do not describe this as eight independently painted animation directions.

`character-motion.ts` gives each champion a performance voice, perceived mass, gait rhythm, cast recovery, and reaction rhythm. These choices affect presentation, not movement allowance, initiative, or spell power. Actual cast release is synchronized across fighters. The generic atlas helper defaults to a 400ms preparation, while the combat host passes the active presentation clock's 360ms anticipation. Do not change the default and assume all combat timing changed with it.

The renderer uses 192 world units for character artwork. `battlefield-geometry.ts` owns the projection: tile half-width 88, half-height 60, horizontal step 176, vertical step 90, elevation step 48, and the shared `(64,104)` sprite foot pivot. The default focused camera targets about 120 CSS pixels per horizontal hex spacing. These are rendering units, not collision radii. Changing CSS image dimensions without preserving the pivot will cause floating feet or incorrect overlap.

Use actual pose changes for anticipation, release, follow-through, impact, and falling. Preserve costume, proportions, skin tone, appendages, and equipment across frames. A rigid rotation, blur, or squash of one still image is not a substitute for newly authored anatomical motion. Creature code currently combines family-specific stepped offsets with selected body-pose changes; its depth of authored animation is deliberately distinguished from the champion sheets.

## Pixel integrity and known repairs

`ChampionFrames` clips a complete cell and uses `image-rendering: pixelated`. Background and mask positions use the same percentages, including at responsive sizes. The current atlas repair is a rendering mask, not a rewrite of source pixels.

`sprite-integrity-v42.ts` records exactly nine reviewed detached opaque pixels across Jan Wicked, Oh Tipi, Oll’ I, The Red Baron, Spai Si, and Treevor. Coordinates are zero-based row, column, x, y. Keep the exact list and the original bytes together. Tests verify that every repair still addresses an isolated opaque pixel and that the mask removes nothing else.

Do not broadly erase disconnected components as “dead pixels.” Eyes, highlights, sparks, and deliberate flying particles can be isolated features. The offline character packer already filters very small alpha islands; any new cleanup threshold requires visual inspection against its source, especially fingers, antennae, and spell particles. The existing integrity test intentionally rejects unreviewed one-pixel islands in packed champion art. This is a defined asset contract, not a universal rule for all effects.

Inspect atlases on light, dark, and checkerboard backgrounds and at the sizes used by the game. Check feet, clipped weapons/wings, mirrored accessories, late image loading, wrong-sized sheets, and frame boundaries. The original atlas fallback is functional continuity, not proof that a missing new sheet was successfully loaded.

## Environment and elemental vocabulary

`living-world-v16.ts`, `reactive-environment-v17.ts`, and `world-readability-v24.ts` choose terrain art, prop placement, cliff edges, occlusion, and continuous boundaries. `CraftedWorldV24.tsx` and `ReactiveTerrainV17.tsx` draw them. The native simulation decides whether a cell is blocked, flooded, frozen, elevated, or hazardous. A rock decoration must not acquire a wall silhouette unless the underlying cell is actually solid.

Scenery variants preserve recognizable forms. Steam does not scorch a tree merely because Fire is one ingredient. Terrain presentation follows the resolved field's dominant mechanics, and expiration restores the natural material. Refreshing the same field should not replay its formation burst.

`element-presentation.ts` is the shared palette and branch authority:

| Base family | Advanced emblem | Main colour | Readable material direction |
|---|---|---|---|
| Fire | Lightning | `#ab431e` | Ember shapes, sharp energetic release |
| Water | Ice | `#176a95` | Droplets, ripples, hard crystalline ice |
| Earth | Metal | `#805827` | Weight, facets, grounded fragments |
| Air | Storm | `#4f6e2c` | Directional ribbons and currents |
| Light | Radiance | `#996718` | Clear stars, protection and restoration marks |
| Dark | Void | `#63458d` | Dense curls and restrained enclosing shapes |

Each palette contains ink, shadow, main, bright, light, and spark colours. Advanced emblems retain the base family's palette and use distinct silhouettes. `spell.branch` selects advanced identity; do not infer it from the spell name or level, and do not grant mechanics such as freezing because an icon happens to depict Ice. `ElementIcon.tsx` is the code-native icon system.

There are 63 field definitions, but effects use a smaller coherent set of ten dominant-mechanic families: mist, ice, cover, current, restoration, hazard, mud, denial, protection, and charge. `reaction-presentation-v44.ts` provides the classification and motif. The complete ingredient recipe remains inspectable; visual family reuse does not mean the mechanics are identical.

`element-effect-frames.ts` builds hard-edged cels once at module initialization and batches pixels into six palette paths. Projectile cels advance every 120ms; impact cels have finite endpoints. Preserve this bounded approach rather than adding one React element or timer per particle.

During planning, `planning-material-v45.ts` chooses at most 18 on-screen temporary-field cells, deterministically distributed across materials. Off-screen cells and excess cells retain static art. Rigid scenery remains planted. `planning-element-v45.css` uses stepped opacity and disables animation under reduced motion.

## One playback clock

`feedback-v16.ts` defines the release-45 presentation boundaries:

| Elapsed time | Display phase |
|---:|---|
| 0–1599ms | Movement |
| 1600–4199ms | Casting; all projectiles release after the shared anticipation |
| 4200–5599ms | Effects and displacement |
| 5600ms onward | Review |
| 6900ms | Animated sequence ends; review remains available without a deadline |

These are views of a simultaneous resolved exchange, not initiative turns. `playback-clock-v44.ts`, `useBattlePlaybackV44.ts`, `usePlaybackAnimationsV44.ts`, and `playback-animation-v44.ts` synchronize sprites, projectiles, effect reveals, native animations, and sound. Pause, phase step, speed, replay, and instant results are local presentation controls. They must not submit orders or advance a co-op floor barrier.

New animation elements need the correct origin. Cast effects originate in casting; terrain-arrival effects originate at impact. An 850ms animation mounted at impact but given exchange-time zero will immediately appear finished. Use the shared binding rather than independent `setTimeout` chains.

Board metadata must come from the active native rules adapter. `BattlefieldSpellRules.spellForCast` carries the optional focused profile and Tower's printed scroll metadata. Replay passes the recorded scroll boolean explicitly; a scroll must not acquire the caster's affinity scaling because its effect renderer asked the ordinary spell catalogue.

## Speech and outcome hierarchy

`exchangeReaction` chooses one recorded reaction, with priority knockout, defeat, critical hit, newly acquired Burn, spent-to-zero Flux after casting, then actual fizzle. Zero damage is not a miss. A knockout line needs one unambiguous hostile spell source; positive surface damage or mixed causes veto that attribution. Creatures use their family sounds rather than their proxy champion's dialogue.

Speech appears only during resolved review, never while aiming. The SVG card uses 14px quote text, wraps rather than types characters in gradually, ignores pointer input, and protects sprite and combat-readout rectangles. Placement includes obstacle-edge candidates, an 8px clearance, and a maximum 96px distance from the actor; the tail itself is capped at 8px. Crowded views may omit a bubble. Per-character/reason cooldowns suppress repeats for the next two rounds while allowing the same replay; round rollback clears the battle-local history.

Humour belongs in a brief response to an actual event. It should not replace an accurate damage figure, protection explanation, condition duration, or actionable error.

## Audio ownership and accessibility

`createGameAudio` allocates/resumes its context only after an explicit player gesture. Sound defaults off. Short element-specific oscillator envelopes are layered with deterministic, 22,050Hz material buffers for step, fire, water, earth, air, light, dark, steam, and ice. These buffers are synthesized locally and cached; there is no network sample request.

Event priority limits cast/contact layers and prefers decisive outcomes. Release 45 adds distinct critical, heal, Burn, and fizzle motifs; healing alone does not play a damage impact. The owner caps overlapping voices at 16 and total scheduled voices at 96. Separate UI and combat buses apply level changes to queued voices with a short gain ramp. Sound enabled at volume zero still schedules bounded silent cues, so raising the level mid-replay can reveal the remaining sounds.

`useBattlePresentationV44.ts` owns preferences and disposal. `hex-presentation-v44` stores sound, instant presentation preference, UI level, combat level, and softer effects. Sound, reduced motion, and instant results are separate choices. “Softer effects” scales audio intensity; it is not a motion setting. Mute/cancel stop outstanding voices; disposal disconnects buses and closes the context. Pause/seek must cancel old voices and reschedule only cues remaining on the shared clock.

Every important audio cue has visible event feedback. Test with sound off, reduced motion, instant results, a suspended audio context, and repeated mount/unmount. Do not claim accessibility certification or acceptable loudness from mocked AudioContext tests: actual listening, keyboard/touch operation, contrast, and device performance remain separate checks.

## Offline reproduction and provenance

The normal application build consumes committed `public/` files. It does not need image generation or run the packers.

The handoff bundles the accepted raw inputs under this portable layout. See [the asset-source README](../../asset-sources/README.md) for the accompanying source manifest and reproduction procedure:

```text
asset-sources/
  frames/raw-a/<original filename>.png
  frames/raw-b/<original filename>.png
  environment/reactive-props-v17.png
```

The content handbook lists the exact accepted filenames. Existing JSON audits retain their historical absolute source paths; use their hashes to match relocated inputs. Do not treat an old developer path as a required installation location. All 30 accepted raw character inputs were present and matched their recorded SHA-256 at inspection, totaling 54,047,366 bytes. The accepted reactive-prop input was 2,362,006 bytes and also matched its audit. These 56,409,372 raw bytes are the accepted external packer inputs selected for the handoff. Earlier exploratory generations are not required to reproduce the current packed outputs. The ground source is already in `public/pixel/environment/wellspring-surfaces-crafted.webp`.

Repack the bundled accepted art from the web application root:

```sh
node scripts/pack-character-animation.mjs oh_tipi asset-sources/frames/raw-a/oh_tipi.png
node scripts/pack-character-animation.mjs djonah_thaan asset-sources/frames/raw-a/djonah_thaan-corrected.png
node scripts/pack-character-animation.mjs juul_i_yaina asset-sources/frames/raw-b/juul_i_yaina.png 2,4
node scripts/pack-environment-v17.mjs asset-sources/environment/reactive-props-v17.png
```

`scripts/import-pixel-assets.mjs <original-root>` is an optional historical refresh tool, not a reconstruction step. It expects a separately supplied original source layout, including `assets/sprites/pixel_cast_v1/manifest.json`; that layout is not guaranteed by the Godot revision at this repository's root. Reproducing this release uses the committed champion atlases, environment sources and portable raw inputs above.

These commands write assets and audits; run them in a reviewable working copy. The original importer requires the original repository's `assets/sprites/pixel_cast_v1/manifest.json` and copies bytes unchanged. The character packer extracts complete alpha islands, thresholds alpha, removes very small islands, applies one scale per character, aligns feet, packs lossless WebP, writes audit records, and regenerates `lib/animation-assets.ts`. The `2,4` flag mirrors only Juul I Yaina's known corrected cel. Djonah Thaan uses the already corrected raw image, not the earlier uncorrected generation.

The environment packer is tailored to one inspected 1254×1254 image and nonuniform cell boundaries. It is not a general automatic atlas importer. A differently laid out new image needs a reviewed import contract rather than a blind rerun.

Both packers import `sharp`. The inspected installation used Sharp 0.35.4; the repository pins that version through the Miniflare override rather than declaring Sharp as a direct tool dependency. Check `node --input-type=module -e "import sharp from 'sharp'; console.log(sharp.versions)"` before packing. A package manager that does not expose the transitive dependency may need an explicit isolated tooling dependency. Do not silently change the runtime dependency tree just to make a packer work. Node's declared minimum is 22.13.0; use the handoff's locked installation procedure.

An isolated reproduction check on 2026-10-20 used Node v24.18.0 and Sharp 0.35.4 on Windows, validated all 31 portable input hashes, and invoked the existing packers in a separate scratch directory. All 30 character atlases, the reactive-prop atlas, and the crisp ground derivative matched their shipped SHA-256: **32 outputs, 32 exact matches**. This includes corrected Djonah Thaan and Juul I Yaina's `2,4` override. Runtime files were not overwritten, and their hashes remained unchanged. The asset-source manifest contains the expected output hashes for further reproduction checks. This verifies reproducible packing with that toolchain, not a new visual acceptance of every frame or a guarantee that a future encoder version emits identical bytes.

Prompts record use of the built-in image generation tool and identity/style references. Re-running a prompt is not deterministic and will not reproduce the same pixels. Preserve accepted raw images, original atlases, frame audits, orientation corrections, and reviewed repair masks. A generation log is provenance, not an external copyright or redistribution license.

`docs/SOURCE-PROVENANCE.md` documents the first import and original portrait history, but contains early six-character/well-scoring descriptions that are historical, not release-45 rules. The environment manifest records an original H.E.X. generation source and claims no third-party pixels; that recorded claim does not establish a blanket license. Do not invent a CC, MIT, public-domain, or commercial-use grant for the art. Preserve original H.E.X. attribution/provenance and existing dependency license files; resolve redistribution terms with the owner where necessary.

## Focused verification

Use the normal development dependencies, then select checks for the asset being changed:

```sh
node --experimental-strip-types --test --test-concurrency=1 tests/character-animation.test.ts tests/art-integrity-v42.test.ts
node --experimental-strip-types --test --test-concurrency=1 tests/element-presentation.test.ts tests/element-effect-frames.test.ts tests/reactive-environment-v17.test.ts
node --experimental-strip-types --test --test-concurrency=1 tests/character-presentation-v45.test.ts tests/audio-material-v41.test.ts tests/presentation-v44.test.ts tests/playback-clock-v44.test.ts
```

The decoding tests need Sharp. Browser validation should separately cover: normal and failed/delayed image loading; all action rows and left-facing playback; complete terrain boundaries; simultaneous interception without phantom impacts; pause/step/speed/replay; sound on/off and mid-playback levels; reduced motion; a 390×844 portrait view and a 790×444 landscape view; and a crowded result where readouts win over optional speech. A deterministic fixture or passing unit test is not a claim of measured frame rate or human artistic acceptance.
